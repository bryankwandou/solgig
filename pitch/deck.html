SolGig is a store built for AI agents. An agent asks for a product and gets HTTP 402 with a price. It pays on Solana, asks again, and leaves with the file and a receipt anyone can check on-chain.

THE PROBLEM

Agents can pay now. They have nowhere to shop.

No card, no bank

An agent cannot pass KYC or a card check. It can sign a Solana transaction.

Rails, not shelves

x402 tools on Solana charge for API calls. None of them list goods from many sellers.

Stores assume a browser

Checkout pages, cookies and captchas block a buyer that is a script.

Source: Colosseum Copilot project search, 26 Sep 2026 · 2

Agents already hold wallets and can pay. What they lack is somewhere to buy things. On Solana, the x402 projects we found are payment rails for API calls. None of them is a catalog of goods from many sellers. And ordinary stores are built for a person in a browser.

THE SOLUTION

Every SolGig product answers HTTP 402 with a price.

Catalog for machines

One JSON endpoint lists every product, price and purchase URL, with a JSON Schema.

SOL or USDC

The 402 lists both, with exact transfers and instructions ready to sign.

Receipt on-chain

The answer carries the transaction signature. Anyone can check the purchase.

No account, no SDK, no API key · 3

The fix is to treat each product as an x402 resource. The catalog tells an agent what exists. The 402 tells it the price in SOL or USDC and exactly what to send. The success response carries a receipt tied to the transaction signature.

HOW X402 WORKS HERE

Nothing ships until the chain agrees.

1 · GET

402 with a signed challenge, 5 min price lock

→

2 · PAY

One Solana tx: seller net plus 2.5% fee

→

3 · RETRY

X-PAYMENT: signature plus payer's signed proof

→

4 · 200

File plus receipt in X-PAYMENT-RESPONSE

Before step 4 the server reads the tx from RPC and checks signer, network, time and balance changes (lamports, or USDC by owner and mint). One signature settles one purchase; a reused one gets 409.

Code: src/lib/x402.ts, src/lib/solana/pay.ts · 11 tests in tests/x402.test.ts · 5

Step one returns a challenge signed by the server that fixes the price for five minutes. Step two is a normal Solana transaction. In step three the agent also signs the challenge and the signature with its key, so nobody who merely saw the transaction on-chain can claim the file. Only then does the server check the chain and answer 200.

FOR PEOPLE TOO

People buy the same listings, with escrow for services.

  • Wallet sign-in, no password
  • Service money held in a program PDA
  • Buyer releases, or reclaims after 14 days
  • Feed, follows and reviews

Every seller is visible to agents and people with no extra work · 8

Human buyers are the supporting side. They see the same listings in a normal storefront. Services settle through the escrow program: money sits in a program-owned account until the buyer releases it, or the buyer takes it back after fourteen days.

BUSINESS MODEL

2.5%

of every sale, taken in the same transaction.

A 1 SOL sale sends 0.975 SOL to the seller and 0.025 SOL to the treasury in one transfer. No invoicing, no payout run. Same split for USDC.

Fee logic: splitAmount in src/lib/fees.ts · 9

We earn two and a half percent per sale. It is part of the payment transaction itself, so there is no invoice and no payout to run. The seller keeps ninety-seven and a half percent.
